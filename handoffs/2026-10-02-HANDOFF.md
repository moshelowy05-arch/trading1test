  - **All Model B dollar figures are provisional until re-scored with official settlement results.** That needs

## 5. Road map from research to a real algorithm (each step has a gate)

| Step | What | Needs | Gate to continue |
|---|---|---|---|
| 1 | Re-score past windows with official results | Mac, no key | Still clearly positive |
| 2 | 28-day forward test (Study 2 Phase A) | Mac or cloud, no key | Pre-registered PASS |
| 3 | Weekly competition probe | Mac, no key | No doubling of deep resting size |
| 4 | Fill reality (order-book recording around sweeps) | **read-only API key** (Moshe creates) | Our order would have been there and filled |
| 5 | Build the bot in paper mode | always-on server (~$5–20/month) + key | Paper results track the simulation |
| 6 | Account, legal and tax prep | Moshe | CPA opinion; API location attestation works for the categories traded; NJ status checked |
| 7 | Tiny live probe (1 contract, a few tens of dollars at risk) | **Moshe's explicit approval**; LiveGuard config | Real fills ≥ 50% of simulated; no reversal problem |
| 8 | Scale slowly (10 → 25 → 50 → 100 contracts) | daily loss limits, kill switch | Live ≥ half of simulated at each size |

Components the bot needs in step 5, all in pmarb style (venue code in `venues/` and `execution/gateways/`, money as
`Decimal`, fail closed):
- **market scanner:** finds markets whose recent price is 20–80c, using the WebSocket trade/ticker feed;
- **order manager:**
  - post-only 3c bids with short expiries (GTD);
  - amend the expiry to keep queue priority;
  - order groups as an exposure cap;
  - per-shard collateral;
  - cancel the moment a market leaves the band;
- **risk:** per-market, per-event and per-day limits; daily loss stop; kill switch; reconcile on any uncertain order
  state;
- **position and settlement tracker**, using official results;
- **logging and alerts**, plus a daily comparison of real against simulated fills.
